# Code Overview: Raftel vs. Damysus

This document describes the structure of the codebase and maps each major
component to the paper's claims.  It is intended to help artifact reviewers
understand what changed relative to the upstream
[Damysus](https://github.com/vrahli/damysus) baseline and why.

---

## Protocol Selection (compile-time)

`App/params.h` selects the protocol via preprocessor macros:

| Macro | Protocol | run.py flag |
|---|---|---|
| `BASIC_HYBRID_TEE` | Raftel | `--p0` |
| `CHAINED_HYBRID_TEE` | Chained_Raftel | `--p1` |
| `BASIC_ACHILLES` | Achilles | `--p2` |
| `BASIC_HOTSTUFF` | Hotstuff | `--p3` |
| `BASIC_DAMYSUS` | Basic-Damysus | `--p4` |

Each protocol is a separate branch of the original Damysus code, compiled
anew for each run.

## Raftel vs. Damysus: What Changed

Raftel extends Damysus to support **partially trusted** topologies where only
a subset of replicas hold a TEE.  The key additions are:

### 1. TEE population parameter (`totaltee`)

`Handler.cpp` receives `totaltee` at startup (node argument position 2).
Replicas 0 … totaltee−1 are `TEE` nodes; the rest are `nonTEE`.  The TEE
quorum size `QT = max(totaltee/2 + 1, f+1)` governs when a certificate can
be issued without a full n−f classic quorum.

**Paper claim (§4–§5):** A TEE quorum of size `f+1` suffices for safety and
liveness when the leader is a TEE node; this is the `Raftel-Best` (S1)
configuration.

### 2. Raftel-Worst (`totaltee=0`)

Setting `--totaltee 0` disables the TEE fast path entirely (no TEE quorum is
ever reachable), forcing the protocol to fall back to the classic `3f+1`
quorum path.  This is the `Raftel-Worst` baseline in Figure 3.

**AE fix:** The original experiment script used `--totaltee f` (= `f` TEE
nodes, not zero), which is a different and stronger condition.  The correct
definition from §7.2 is `m=0`.

### 3. Fixed-leader mode (`--leader-mode fixed`)

`Handler.cpp` supports a `fixed` leader mode in which the leader is always
replica `leader_id` rather than rotating by view.  Figure 4 uses this to
separate the effect of TEE leadership (S1/S2, leader_id=0) from non-TEE
leadership (S3/S4, leader_id=f+1).

## SGX Simulation vs. Hardware Mode

`Makefile` accepts `SGX_MODE=SIM` or `SGX_MODE=HW`. All local and cloud
experiment scripts pass `--sgx-mode SIM` to `run.py`; hardware mode remains an
explicit opt-in for manual runs. `run.py` forwards the selected mode to the
make invocation and raises an error if the build fails.

Both `./ae smoke` and `./ae run` use SIM mode by default.
